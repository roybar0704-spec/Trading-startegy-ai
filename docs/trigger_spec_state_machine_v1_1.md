# Trigger Spec + Entry State Machine — v1.1

**סטטוס:** קפוא. מוזג ל-Rules v1.1 — חלק מה-Spec (ר' `HANDOFF_MASTER.md`, `SPEC_V1_FROZEN.md` §14 מפנה לכאן לדיאגרמה המלאה). כותרת "Draft"/"לאישור" הייתה שארית מלפני סגירת התכנון הרשמית (2026-07-08) ותוקנה כאן בלבד — ללא שינוי תוכן.
**מוסכם ונעול:** קריאה 2 — רצף R → S → iFVG, ללא דילוג על שלבים.
כל ההגדרות כתובות ללונג (Demand). שורט = תמונת מראה מלאה.

---

## 1. הגדרות פורמליות — R ו-S (5M)

**Engagement (מגע באזור):** הרגע הראשון שבו מחיר Mid נכנס לטווח ה-4H FVG התקף
(`mid ≤ fvg.top` ללונג). נרשם `engagement_ts`. המגע עצמו יכול להתרחש גם לפני חלון המסחר (ראה H1).

**נר R (Reaction):** נר 5M סגור המקיים את כולם:
1. `R.low ≤ fvg.top` — נסחר בתוך האזור.
2. `R.close > R.open` — גוף בכיוון האזור.
3. `R.low < min(R.open, R.close)` — קיים Wick תחתון. **Pool = R.low**.
4. בזמן סגירתו: `mitigation_pct < 100%`.

אם נר מאוחר יותר עומד בכל תנאי R — הוא **מחליף** את R (R = המועמד האחרון לפני S).
נר 5M ש**נסגר** מתחת ל-R.low (Close-Through, לא Sweep) → R מבוטל, חוזרים לסריקה.

**נר S (Sweep):** נר 5M אחרי R המקיים:
1. `S.low < R.low` — לקח את נזילות ה-Wick של R.
2. `S.close > R.low` — נסגר חזרה מעל הרמה שנלקחה.

רק לאחר **סגירת S** מתחילה סריקת iFVG ב-1M. (שלבים 1–7 שנעלת — ללא שינוי.)

## 2. iFVG — הגדרה פורמלית מלאה (ההצעה לאישור)

### 2.1 מועמד (Candidate)
FVG **דובי** ב-1M: תבנית 3 נרות שבה `c1.low > c3.high`.
אזור המועמד: `[gap.bottom = c3.high, gap.top = c1.low]`.
תנאי מועמדות: נוצר בין `engagement_ts` להווה, וטרם עבר Inversion.
**אין מינימום גודל** (עקבי עם חוקי ה-4H FVG).

### 2.2 Inversion (לידת iFVG)
נר 1M ש**נסגר** מעל `gap.top` — סגירת גוף מלאה, עקבי עם פילוסופיית ה-BOS שלך:
Close-through = Inversion; Wick-through בלבד = כלום (המועמד נשאר אינטקטי).

**תנאי זמן:** סגירת ה-Inversion חייבת להתרחש **אחרי** סגירת S (שלב 6 ברצף).
המועמד עצמו רשאי להיווצר לפני או אחרי S — מה שקובע הוא מועד ה-Inversion.

### 2.3 בחירה כשיש כמה
- נלקח **ה-Inversion הראשון כרונולוגית** אחרי סגירת S.
- אם נר אחד הופך כמה מועמדים בו-זמנית (נר חזק שסוגר מעל כמה Gaps מוערמים):
  נבחר ה-Gap עם ה-`top` **הגבוה ביותר** (הקרוב למחיר) — הוא מגדיר את "תחילת ה-iFVG".

### 2.4 שימוש
- **קצה הכניסה** ("תחילת ה-iFVG") = `gap.top`.
- M1: Limit ב-`gap.top` | M2: Market בסגירת נר ה-Inversion | M4: מגע ב-`gap.top` + נר דחייה 1M שנסגר מעלה → Market בפתיחת הנר הבא.
- **בדיקת גאומטריה:** `entry − SL ≥ min_stop_distance`, אחרת Setup נפסל (`invalid_geometry`). זה סוגר את המקרה שבו iFVG עמוק שם כניסה מתחת לסטופ.

### 2.5 פסילת iFVG / Setup (לפני מילוי)
| טריגר | תוצאה |
|---|---|
| נר 1M נסגר מתחת ל-`gap.bottom` (Re-Inversion) | iFVG מת → Setup מת |
| Mid < `S.low` (שבירת נקודת ה-Sweep) | Setup מת — הפרמיז נשבר |
| 4H FVG מגיע ל-Mitigation 100% | Setup מת |
| היפוך Bias | פקודות תלויות מבוטלות, Setup מת |
| סוף חלון / תחילת Blackout | פקודות מבוטלות (`expired` / `blocked_news`) |

**ברירת מחדל: אין Re-Arm.** Setup = ניסיון כניסה אחד על iFVG אחד. iFVG שמת → Setup מת. דגל `allow_ifvg_rearm` (כבוי) קיים לניסוי עתידי בלבד.
אם לא נוצר אף iFVG עד סוף החלון → `outcome = no_ifvg` (נרשם ביומן — נתון מחקרי חשוב בפני עצמו).

## 4. חורים חדשים שהדיאגרמה חשפה (בדיוק כפי שההמלצה צפתה)

**H1 — היכן חייב הרצף להתרחש ביחס לחלון?**
"כניסות בלבד 08:30–10:30" — אבל R ו-S יכולים תיאורטית להיווצר ב-07:00.
**הצעה:** מגע ב-4H FVG רשאי לקרות לפני החלון; **סגירת R, סגירת S והכניסה — כולם בתוך החלון.** כך "כניסות בלבד" נשמר והרצף דטרמיניסטי. (חלופה לניסוי עתידי: לאפשר R/S טרום-חלון.)

**H2 — Race Condition ב-09:00 ET:** נר 4H, 5M ו-1M נסגרים באותה שנייה בדיוק.
**הצעה:** עיבוד דו-שלבי בכל חותמת זמן — שלב א': כל אירועי הסגירה מעדכנים את ה-Store (סדר: 1M→5M→4H); שלב ב': לוגיקת החלטות רצה פעם אחת על המצב המעודכן. אפס תלות בסדר מקרי.

**H3 — Setups מקבילים:** Bias מתיר כיוון אחד, אבל ייתכנו שני אזורי 4H פעילים באותו כיוון.
**הצעה:** מקסימום Setups חמושים במקביל = המכסה שנותרה; עדיפות לפי חוק §4 (BOS → Displacement → קרבה) [תוקן מ-"§14" — התייחסות שגויה שנותרה מלפני איחוד המסמכים; אין שינוי בכלל עצמו, ר' Design Review Phase 3]. הבהרה נוספת (D-052): אכיפת המכסה עצמה היא פר-תיק, לא גלובלית — ר' SPEC_V1_FROZEN.md §10.

**H4 — כניסה חוזרת לאותו אזור:** אחרי סטופ, ה-4H FVG עדיין תקף (מיטיגציה < 100%).
**הצעה:** רצף R→S→iFVG חדש באותו אזור מותר (המכסה מגבילה ל-2 בכל מקרה) + תג `same_zone_reentry` לניתוח נפרד.

**H5 — צביר החדשות של 08:30:** NFP/CPI יוצאים בדיוק בפתיחת החלון → בימים אלה אין כניסות עד 09:00; חדשות 10:00 (ISM) מחשיכות את 09:30–10:30. ביום NFP+ISM החלון כמעט כולו חסום.
**הצעה:** לא באג — אבל היומן ירשום `effective_window_minutes` לכל יום, כדי שציפיות כמות-העסקאות והסטטיסטיקה יהיו מכוילות.

**H6 — ימי מסחר דלילים:** חצאי-ימים וחגים אמריקאיים (Thanksgiving וכו').
**הצעה:** לוח חגים → תיוג סשן `thin_liquidity`. לא מחריגים ב-v1, מנתחים בנפרד.

**H7 — מילוי Limit, כלל חד-משמעי:** קניית Limit מתמלאת כאשר `Ask ≤ limit_price`, במחיר ה-Limit, ללא Slippage חיובי. שמרני ודטרמיניסטי.

## 5. מחקר ה-SL — עיצוב ההשוואה (R-Body מול S-Body)

ההחלטה נדחתה לנתונים — נכון. כך זה ייבנה:

**זרועות מוצהרות מראש:** `sl_anchor ∈ {R_body, S_body}`
- `R_body`: SL = `min(R.open, R.close) − buffer`
- `S_body`: SL = `min(S.open, S.close) − buffer`

**שיטה:** Multi-Portfolio על אותו Setup Stream בדיוק — כמו השוואת M1/M2/M4. כל זרוע מקבלת תיק, מכסה והון משלה → השוואה זוגית (Paired) על אירועים זהים. שים לב לשרשרת ההשפעה: עוגן שונה → מרחק סטופ שונה → **גם גודל פוזיציה וגם מרחק TP (3R) שונים** → WR ו-Expectancy אינם ניתנים לגזירה זה מזה, חייבים סימולציה מלאה. המדדים שביקשת (WR / Expectancy / DD / איכות ביצוע חי — דרך רגישות ל-Slippage ו-Delay) יופקו לכל זרוע.

**תצפית מבנית שחובה עליי להציף (סעיף 12 שלך):** שני העוגנים שהגדרת יושבים על *גוף* — כלומר **שניהם מעל S.low, בתוך טווח ה-Wick של ה-Sweep.** ריטסט מלא של נקודת הנזילות שנלקחה יעצור את שתי הזרועות. אם הכוונה המקורית שלך הייתה "מתחת לנזילות", העוגן הטבעי הוא `S_wick` (= `S.low − buffer`). אני **לא** מכריע — רק מציע להוסיף `S_wick` כזרוע שלישית באותה השוואה. עלות אפס בארכיטקטורה, והנתונים יענו גם על השאלה הזו.

**הצהרת Grid מראש (Anti-Snooping):** 3 מודלי כניסה × 2–3 עוגני SL = 6–9 תיקים מקבילים על Stream זהה. הכל נרשם ב-Experiment Tracker לפני ריצה ראשונה; פונקציית המטרה נעולה; Hold-Out לא נפתח עד הסוף.
